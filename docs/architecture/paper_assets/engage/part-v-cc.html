Quick check · §26

1. How does Trinity Consciousness give O+V a "senior engineer's memory" without retraining any model?

Through structured episodic records that are consulted at the right moments in the pipeline, not through parameter-weight updates (§26).

2. How does the consciousness layer reach the pipeline, and with what authority?

Through two bridges, ConsciousnessBridge and GoalMemoryBridge. Its authority is advisory only: it cannot override the Iron Gate or any safety-critical decision (§26.1, Figure 7).

Quick check · §27

1. What does the co_failures map add that a per-file success rate cannot?

It records which files tend to fail together with this one. A success rate describes one file in isolation; co-failures describe coupling between files (§27).

2. What does the 168-hour TTL do to a file's reputation?

Records older than a week, by default, decay. A file's reputation therefore reflects recent behaviour, and old failures stop counting against it (§27).

3. What is the concrete payoff of MemoryEngine at CLASSIFY?

If a target file's success rate is below 0.5 or its fragility is high, the risk tier is raised. That is how the organism avoids breaking the same file again and again (§27).

Quick check · §28

1. A file has a perfect history, zero fragility and no dependents. What is its risk score, and why is it not zero?

0.1, which is LOW. The formula adds a fixed 0.1 baseline, so no change is scored as entirely risk-free (§28).

2. Why does escalation happen at CLASSIFY rather than after a failure?

It is preventive: a HIGH or CRITICAL file earns extra oversight before the operation runs, not after it has already broken something (§28.1).

Quick check · §29

1. Which work does HealthCortex suppress when the system is under resource pressure, and why that work?

Exploration-type sensors such as OpportunityMiner and DocStaleness. Their work is optional, so suppressing them avoids adding load to a system that is already strained (§29.1).

2. O+V generally avoids polling. Why is polling accepted here?

"The system is tired" is a continuous state, not a discrete event, so there is no event to subscribe to. The 30-second interval is explicit and slow, not a tight retry loop (§29.2).

Quick check · §30

1. Why are blueprints keyed on (repo_sha, policy_hash)?

A blueprint is only valid while the code and the policy it was computed against are unchanged. Keying on both means a blueprint is used only by an operation that matches that exact state (§30).

2. What does the 120-minute daily budget bound?

How much idle time can be spent dreaming. Once it is used up, dreaming is suppressed until the next daily reset, so speculative work cannot consume resources without limit (§30).

Quick check · §31

1. How do CAI and SAI divide the work?

CAI covers what is happening in the codebase: hotspots, coupling and drift. SAI covers when and why: temporal patterns and causal chains such as post-deploy cascades. UAE fuses the two into one OperationAwareness object (§31).

2. Why is UAE's fused confidence bounded by the less confident of CAI and SAI?

A fusion should not claim more certainty than its weakest input supports. Taking the lower bound stops one confident component from hiding the other's uncertainty (§31.3).

3. What changes when the awareness level rises toward HYPERAWARE?

Higher levels trigger deeper context expansion and more sensitivity to human escalation (§31.3).

record_operation_outcome() at POST-APPLY writes outcomes back into MemoryEngine and GoalMemoryBridge. The other four consult the engines and return advice (§32.1).

is_system_healthy_for_exploration(), at intake gating. It returns (healthy, reason) from HealthCortex so that ProactiveDriveService can decide whether to fire exploration sensors at all (§32.1).

By default the top 5 most semantically similar past operations: their outcomes, rationales and file touches, rendered as an ## Episodic Context section (§33).

Reconstruct why the organism made each decision. The log records each phase of its reasoning, from memory recall and tool choices to L2 repair progress and post-apply outcomes (§33.1).

Quick check · §34

1. Why does secret redaction run before any model sees the content?

It is Tier -1 deterministic: a secret pasted into the REPL is removed on its way in, so it never reaches a model's prompt in the first place (§34.1).

2. Why do postmortem entries expire after 600 seconds by default?

So that stale closures from earlier operations do not pollute new sessions (§34.2).

3. Where, and only where, is ConversationBridge's output consumed?

By StrategicDirection at CONTEXT_EXPANSION. It has zero authority over the Iron Gate, UrgencyRouter, risk tier, policy engine, FORBIDDEN_PATH or approval gating (§34).

Quick check · §35

1. How does LastSessionSummary pick the most recent prior session?

It takes the lexically greatest bt-* session directory, skipping the current one. The directory names embed the timestamp, as in bt-2026-04-15-230849, so lexical order is time order (§35).

2. Why render each session as one dense, deterministic line?

It carries the key facts (stop reason, duration, counts, apply mode, verify result, commit) into the strategic-memory prompt in very little space, and the same session always renders the same way (§35).

Quick check · §36

1. Why is the semantic boost capped at 1 while the hard goal_alignment_boost is 2?

Inferred themes must stay strictly subordinate to declared goals. With the lower cap, inference can nudge priority but cannot outrank declared work, which avoids starvation (§36).

2. What does halflife decay fix about naive goal inference?

Naive inference drifts: a session focused on one bug makes later signals look like more of that bug. With decay, recent work weighs more than older work, so the inferred theme follows current priorities while still carrying durable themes (§36.1).

Quick check · §37

1. Strategic Direction injects both the principles and recent git momentum. What does each tell the model?

The principles say what the code must align with. The momentum section, built from the last 50 commits, says what the team is currently working on (§37.2, §37.3).

2. What failure does §37.4 say the injection guards against?

Generic code that works but hides the problem, such as a one-line patch that suppresses a test failure. With the mandate "structural repair, not patches" in the prompt, the model is pushed toward fixing the root cause (§37.4).

Quick check · §38

1. What closes the six-layer loop into a cycle?

The feedback step after Layer 6: consciousness learns from the outcome. MemoryEngine updates file reputation and GoalMemoryBridge stores the operation, so the next operation benefits (§38).

2. Match the layers to the questions the paper assigns them.

Strategic Direction: where are we going. Consciousness: why evolve. Event Spine: when to act. Pipeline: what to do, safely. Venom: how. ChangeEngine and AutoCommitter persist the result (§38).
