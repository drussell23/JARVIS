Quick check · §79

1. Why does an 'infra' classification on iter=1 kill the op, rather than trigger another retry?

The 'infra' class is non-retryable by design, and it triggers _early_return_ctx escalation. So a transient sandbox or pytest flake ends the op. See §79.1.

2. What does the workaround JARVIS_MAX_VALIDATE_RETRIES=0 give up?

It skips iter=1 completely. That avoids the flake, but it also removes the retry iteration for every op, not only the ones that would have flaked.

3. §79.3 has no workaround. Why is it still on the list?

The hardcoded 90-second asyncio.wait_for is itself the emergency fix, but it is not parameterized. The proper fix is an env-driven timeout consistent with the rest of the pipeline's budget allocation.

Quick check · §81

1. How does EphemeralUsageTracker decide that two goals belong to the same capability class?

It normalizes each goal, removes stop words and hashes the canonical form. Goals with the same hash count towards the same class, and the threshold (JARVIS_GRADUATION_THRESHOLD=3) fires exactly once per class. See §81.3.

2. What happens if a graduation sits in AWAITING_APPROVAL too long?

Hardening requirement H4: after the approval timeout (30 minutes by default) the worktree is discarded and the event is logged.

3. What does a graduated capability become, and has multi-file APPLY graduated?

It becomes a permanent agent: a durable code path that future operations call directly instead of regenerating it. Multi-file APPLY has not graduated yet. Simpler capabilities, such as individual test-generation patterns and single-file refactors, have. See §81.4.
