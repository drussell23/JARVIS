Quick check · §1

1. At each pipeline phase an operation has four possible fates. What are they, and why does it matter that two of them are neither "go" nor "stop"?

An operation may proceed, be queued for later, be escalated for human review, or be rejected (§1.1). Queueing and escalation let the system defer work when a budget is exhausted, or hand risky work to a human, instead of forcing a yes/no choice. That is how it "falls back gracefully" rather than burning resources or paging a human at 3 AM.

2. A bad change surfaces six months later. Which records from §1.2 let you rebuild what happened?

Every operation has an identifier, and every phase transition goes to an append-only ledger. Every model call is recorded with its cost. Every applied change is a git commit whose message names the operation ID, the risk tier and the provider. The ledger plus the git history give the full causal chain.

3. In the name "Ouroboros + Venom", which half supplies the discipline and which supplies the capability?

Ouroboros is the governance skeleton: the discipline. Venom is the agentic execution layer that lets the model read files, search code, run tests and revise its output over several turns: the self-improvement (§1.3). The paper says neither works without the other.

Quick check · §2

1. What still works if the consciousness bridge is turned off, or if JARVIS_GOVERNED_TOOL_USE_ENABLED=false?

Without the consciousness bridge, operations still complete, but without reputation-driven risk assessment. With the tool loop off, the system falls back to single-shot generation. Both follow from the claim that each layer has a clean interface and can be tested on its own.

2. How can the orchestrator call a provider without knowing whether it is Claude, DoubleWord, Prime or a test mock?

It imports providers through a CandidateProvider protocol. Under the "no hardcoded model names" rule, every model reference is resolved at runtime from brain_selection_policy.yaml or an environment variable. Onboarding a new provider changes the policy file, not the code.

3. Why does the BackgroundAgentPool use a different watchdog timeout for each route instead of one timeout?

The routes carry different kinds of work, so the watchdog limits differ: IMMEDIATE 60 s, STANDARD 120 s, COMPLEX/BACKGROUND 180 s, plus grace and tool-loop overhead. One short timeout would kill heavy architectural work. One long timeout would let urgent work hang. With three workers and a 16-slot queue, concurrency stays bounded either way.

Quick check · §3

1. Under Principle 2, what does the service do if the codebase index is not ready, and what failure does that avoid?

It runs _oracle_index_loop as a background task and accepts operations without waiting. If the index is stale, operations run with stale-index warnings instead of failing. This avoids a blocking boot chain, where one slow dependency would hold up the whole system.

2. Principle 3 says "zero polling", yet DoubleWord's Tier 2 polls. How does the paper reconcile the two?

Tiers 0 (SSE streaming) and 1 (webhooks) do not poll. Tier 2 is a safety net used only when webhooks are unavailable. Even then it uses exponential backoff with jitter, not polling on a fixed interval.

3. Principle 4 calls the organism's memory "episodic, not parameter-weight". Name two concrete stores that make this true.

Any two of these: the MemoryEngine's FileReputation records (168-hour TTL), the UserPreferenceMemory's typed entries that persist across sessions, and the LastSessionSummary, which reads the previous session's summary.json at CONTEXT_EXPANSION. All three are records on disk, not changes to model weights.

Quick check · §4

1. Why does §4 argue that an agent's discipline must be structural rather than behavioural?

Fear disciplines a human maintainer: fear of breaking the build, of a pager, of code review. An agent has no such fear. Its discipline therefore has to be built into the system, which is what §4 says O+V is.

2. The §4 invariant lists three kinds of work the organism may never do. What are they?

Work the human would not have sanctioned, work that cannot be audited, and work that cannot be rolled back. Within those limits, it may do any maintenance work that can be described as a procedure, at any hour, under its own budget. That is the "bargain" of procedural autonomy in exchange for structural discipline.
