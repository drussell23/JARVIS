# Slice 11 — VERIFY-Root Unification + Governed WorkspacePromoter Implementation Plan

**Goal:** Close the Run #21 blocker: an op whose APPLY was redirected into the session workspace worktree (Slice 56 / `JARVIS_AUTO_COMMIT_WORKSPACE`) is judged by a VERIFY that statically anchors the boot-time `project_root` — so a **correct** repair structurally cannot pass VERIFY (`pass_rate=0.75` terminal on the chaos-lineage fix), and because **no promotion path exists by design** (`worktree_manager.py:526-531`), the fix never reaches the shared tree and TestWatcher loops forever. Slice 11 makes the op self-consistent (*the tree you wrote is the tree you judge*) and adds a governed, fail-closed promotion step so verified repairs actually land.

**Architecture:** (A) One canonical, dynamic **execution-root seam** — a single resolver function owned by `autonomous_workspace.py`, consumed by `ChangeEngine` (which today owns a private copy) *and* surfaced natively on `GovernedLoopConfig` as a dynamic property — so every VERIFY-side consumer (scoped verify, PatchBenchmarker, verify-gate rollback) resolves the same tree APPLY wrote, on **both** duplicated VERIFY paths (orchestrator inline + Slice4bRunner, the live one). (B) A **WorkspacePromoter** integrated into the existing AutoCommit terminal sequence: after commit-green, it promotes the op's commit(s) from the `ouroboros/auto/<session>` branch onto the operator tree via `WorktreeManager` async git plumbing (`cherry-pick` / `merge --ff-only`, never force), fail-closed with typed states, reusing the existing LiveWork gate coroutine, the existing GENERATE-hash drift checker, and git-native abort as rollback. Master-flagged: A1 driver ON, production default OFF (Sovereign Execution Boundary preserved — the Orange PR path remains the production posture). (C) The bulletproof UUIDv7 flag-audit fix on both sides of the contract (emit full op-ids; auditor excuses ambiguous prefixes only when *every* candidate is provably outside the chaos lineage).

**Tech Stack:** Python 3.9+ stdlib + existing governance modules only; pytest TDD; no new dependencies.

## Global Constraints

The four user-locked architectural mandates (2026-07-13), verbatim intent:

1. **Root-Cause Only** — no env-var checks hot-patched into `orchestrator.py`. The configuration layer itself must expose the effective root, resolving through the SAME dynamic seam `ChangeEngine` uses. *Design note (mandated-scope interpretation, surfaced for operator veto):* the literal form "the entire `GovernedLoopConfig.project_root` resolves to the workspace" would break **observation**: the workspace worktree is a HEAD snapshot, so TestWatcher/sensors pointed at it would never see the (uncommitted) chaos mutation or live human activity — Run #22 would be a no-op soak. The root cause is that `project_root` **conflates two roles**. This plan names them: `project_root` keeps the *observation* role (sensors, TestWatcher, intake — they watch the operator's real tree), and a new dynamic `GovernedLoopConfig.execution_root` property carries the *mutation/judgment* role (APPLY, VERIFY, benchmark, rollback, commit), natively resolving through the canonical seam **at read time** (the env is exported by ledger-sovereignty boot *after* config construction — a static field can never be correct; the property is the only sound shape).
2. **Architectural Purity** — the promoter is fully async and state-driven: `WorktreeManager` methods built on the existing `_run_git_capture` plumbing; `git cherry-pick` (or `merge --ff-only` when applicable); conflict → `cherry-pick --abort` → typed fail-closed `PromotionError` state. **Never** `push --force`, never `reset --hard` on the operator tree, no shell scripts, no `git` invocations outside `WorktreeManager`.
3. **DRY** — promotion lives inside the existing AutoCommit terminal sequence (Slice4bRunner phase 8b, `slice4b_runner.py:1348-1407`), not a new phase. The LiveWork consult reuses the shared `Orchestrator._live_work_apply_gate` coroutine (`orchestrator.py:12484`); the drift re-check reuses `_should_block_apply(ctx.generate_file_hashes, root)` (`slice4b_runner.py:544-546`) pointed at the *promotion target* tree; failure handling reuses the existing POSTMORTEM/quarantine flow (the workspace branch **is** the quarantine — on any promotion failure it persists untouched, exactly as today). `ChangeEngine._effective_write_root` is refactored to delegate to the canonical seam (one resolver, three consumers) with a byte-identical behavior pin.
4. **Bulletproof** — the Iron Gate emit at `orchestrator.py:6504-6507` logs the **full** `op_id` (plus a sweep of every `_FAMILY_SIGNALS` "rejected"-marker emit site for `[:12]`/`[:16]` truncation); the W4 resolver gains `resolve_op_candidates()` and the flag-audit excusal rule: prefix ambiguity is excusable **iff every** matching candidate deterministically resolves outside the chaos lineage — if *any* candidate is in-lineage or the set is empty, poison exactly as today (fail-closed preserved).

Repo-wide conventions (CLAUDE.md): Python 3.9+ (`asyncio.wait_for`, never `asyncio.timeout`), `from __future__ import annotations` everywhere, env-var-driven tunables with sane defaults, async-first, zero hardcoded model names. **Every commit ends with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.**
